# [[Cyber-Threat Hunting Concepts]]

| Concept                         | Description                                                                                                                                        |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Intrusion Detection Limitations | Even with advanced security systems, intrusion attempts ==cannot be detected 100% of the time== due to the ever-evolving nature of cyber threats.  |
| Threat Actor Adaptability       | Cyber ==threats constantly adapt== to new detection methods, making it a constant struggle for defenders to stay ahead.                            |
| Undetected Intrusions           | It is assumed that somewhere in the network, an undetected intrusion has already occurred, and threat actors may have a foothold.                  |
| Cyber Threat Hunt Objective     | ==Assume network compromise and search== for signs of entry to prevent malicious actions.                                                          |
| Security Guard Analogy          | ==Similar to a security guard patrolling== an office building, ensuring security measures are functioning and no unauthorized access has occurred. |
| Security Measures               | Includes ==security alarms, locks, fences, and network security protocols.==                                                                       |
| Threat Detection Method         | ==Proactively detect malicious activity== not identified by traditional alerting mechanisms.                                                       |
| Threat Actor’s Evasion          | Threat actors ==may evade antivirus and IPS== definitions, ==but their activity can be detected== through tell-tale signs.                         |
| Data Analysis                   | Analyze authentication ==logs, event data, and traffic flow== to correlate data and identify potential threats.                                    |

# [[Cyber Threat Hunting Cycle]]

| Stage             | Goal                                                                | Actions                                                                                                          |
| ----------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Hypothesis        | Form a hypothesis about a potential attack.                         | Consider the attacker’s motives, methods, targets, and end goals.                                                |
| Investigate       | Validate the hypothesis.                                            | Analyze logs, query data sets, and use other tools to determine if the hypothesis is plausible.                  |
| Uncover           | Discover the attacker’s tactics, techniques, and procedures (TTPs). | Investigate specific IOCs and TTPs to determine what activities support them.<br>Link and Document the attack.   |

# [[CVSS — Common Vulnerability Scoring System]]

## Key Metrics

| Metric Category           | Description                                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **Base Metrics**          | Intrinsic characteristics of a vulnerability that are constant over time and across environments. Includes exploitability and impact metrics. |
| **Temporal Metrics**      | Characteristics of a vulnerability that evolve over time, such as exploit code maturity and remediation level.                                |
| **Environmental Metrics** | Customizable metrics that allow analysts to adjust the CVSS score based on the importance of the affected IT asset to an organization.        |

## Base Metrics

| Metric                         | Description                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **Attack Vector (AV)**         | Context by which vulnerability exploitation is possible (Physical, Local, Adjacent, Network).           |
| **Attack Complexity (AC)**     | Conditions beyond the attacker's control that must exist to exploit the vulnerability (Low, High).      |
| **Privileges Required (PR)**   | Level of privileges an attacker must possess to exploit the vulnerability (None, Low, High).            |
| **User Interaction (UI)**      | Indicates whether user participation is required for exploitation (None, Required).                     |
| **Scope (S)**                  | Ability for a vulnerability in one component to impact resources beyond its means (Unchanged, Changed). |
| **Impact Scoring:**            | —                                                                                                       |
| **Confidentiality Impact (C)** | Impact on confidentiality of information resources (None, Low, High).                                   |
| **Integrity Impact (I)**       | Impact on integrity of information (None, Low, High).                                                   |
| **Availability Impact (A)**    | Impact on availability of the impacted component (None, Low, High).                                     |
### Base scoring
- Base scoring is computed by the vendor or originator with the intention of being published.
- Once it is set, it is not expected to change.
- Scores are computed from the big three: confidentiality, integrity, and availability.
- Temporal and environmental metrics modify scoring.
- The base score has the largest bearing on the final score and represents vulnerability severity.

## Temporal Metrics
The Temporal metrics measure the current state of exploit techniques or code availability, the existence of any patches or workarounds, or the confidence in the description of a vulnerability.

### 1t. Exploit Code Maturity (E)

| Description                                                                                                             | Possible Values                                                             | Impact on Vulnerability Score                                |
| ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Likelihood of vulnerability being attacked based on exploit techniques, code availability, and real-world exploitation. | Not Defined (ND), Proof of Concept (PoC), Functional (F), High (H), Low (L) | Increases with availability and ease of use of exploit code. |

### 2t. Remediation Level (RL)
The Remediation Level of a vulnerability is an important factor for prioritization.

| Remediation Level | Description                                               |
| ----------------- | --------------------------------------------------------- |
| Official Fix (O)  | A permanent solution provided by the vendor.              |
| Temporary Fix (T) | A temporary solution provided by the vendor or community. |
| Workaround (W)    | An interim solution provided by the vendor.               |
| Unavailable (U)   | No solution available or it is impossible to apply.       |
| Not Defined (X)   | No known solution exists.                                 |
### 3t. Report Confidence (RC)

| Report Confidence | Description                                                                                                                                                       | Example                                                                                                                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Not Defined (X)   | No information about the vulnerability is available.                                                                                                              | The vendor has not released any information about the vulnerability.                                                                                                                                       |
| Confirmed (C)     | The vulnerability exists and there is public information about it.                                                                                                | The vendor has released information about the vulnerability.                                                                                                                                               |
| Reasonable (R)    | Published, but researchers cannot to confirm all of the interactions that may lead to the result.<br>Reproducible and at least one impact is able to be verified. | An example is a detailed write-up of research into a vulnerability with an explanation (possibly obfuscated or “left as an exercise to the reader”) that gives assurances on how to reproduce the results. |
| Unknown (U)       | The vulnerability may exist, but there is no public information about it.                                                                                         | The vendor has not released any information about the vulnerability, but there are rumours that it exists.                                                                                                 |

### Temporal scoring
- Temporal scoring is computed by vendors and coordinators for publication.
- It modifies the base score of a vulnerability.
- Temporal scoring introduces mitigating factors that reduce the score of a vulnerability.
- These factors are re-evaluated at specific intervals as a vulnerability ages.
- The temporal score represents the urgency of a vulnerability at specific points in time.
## Environmental Metrics

### 1e. Security Requirements (CR, IR, AR)

Made up of 3 Metrics, can be defined as L,M,H,X (Not defined)
- Confidentiality Requirement (CR)
- Integrity Requirement (IR)
- Availability Requirement (AR)

### 2e. Modified Base Metrics 
Impacts on Base Metrics, can be defined as L,M,H,X (Not defined)

| Metric                 | Description                                           |
| ---------------------- | ----------------------------------------------------- |
| Exploitability         | How easily a vulnerability can be exploited.          |
| Scope                  | The potential impact of a successful exploit.         |
| Privileges Required    | The privileges required to exploit the vulnerability. |
| Impact                 | The consequences of a successful exploit.             |
| Confidentiality Impact | The potential impact on confidentiality.              |
| Integrity Impact       | The potential impact on integrity.                    |
| Availability Impact    | The potential impact on availability.                 |
### Environmental scoring
- Environmental scoring is an optional computation by end-user organizations.
- It adjusts the combined base-temporal score.
- The adjusted score represents a snapshot in time.
- It is tailored to a specific environment.
- User organizations should use environmental scoring to prioritize responses within their own environments.
## Comparisons

|Concept|Description|
|---|---|
|Base Metrics|Intrinsic characteristics of a vulnerability that are constant over time and across environments.|
|Temporal Metrics|Characteristics of a vulnerability that evolve over its lifetime.|
|Environmental Metrics|Characteristics tied to a specific user's environment that modify the base metrics.|

## Cyber hunt operators

- CVSS Score Interpretation: High CVSS scores indicate high vulnerability severity, requiring immediate remediation.
- Vulnerability Prioritization: CVSS helps prioritize remediation efforts based on vulnerability severity.
- Hunt Operator’s Role: Cyber hunt operators identify vulnerabilities and assess their CVSS scores to determine remediation priority.

# [[Hot Threat Dashboard]]

Key Processes

|Process Step|Description|
|---|---|
|Posting a Hot Threat|Security analysts can initiate a hot threat by logging into a portal and providing necessary details about the threat.|
|Reviewing a Hot Threat|A senior investigator reviews the posted threat to validate its criteria and add context.|
|Monitoring Hot Threats|The SOC team conducts automated hunts through data streams to detect matches with hot threat IOCs.|
|Retiring Hot Threats|Threats are retired from the dashboard after 30 days or when their importance diminishes significantly.|

Key Challenges

- Struggle to effectively incorporate the hot threat dashboard into their existing processes.
- Ensuring current threats while retiring outdated ones can be challenging.

Key Intelligence Sources

- **Talos**: A threat intelligence organization that provides insights and data on emerging threats.
- **ISACs (Information Sharing and Analysis Centers)**: Organizations that facilitate the sharing of information about cybersecurity threats among members.
- **Open Source Intel-sharing Forums**: Platforms where security professionals share information about vulnerabilities and threats.

Communication Techniques

- **Traffic Light Protocol (TLP)**: A system used to classify and share sensitive information based on four color-coded designations (Red, Amber, Green, White) to control the flow of information.

Concept Comparisons

|Concept|Description|Key Differences|
|---|---|---|
|Hot Threat Dashboard|A tool for monitoring current high-priority threats in a network.|Focuses on a limited number of threats for efficiency.|
|Traditional Monitoring|Continuous monitoring of all threats without prioritization.|May lead to information overload and less effective response to critical threats.|

## Managing Hot Threats

1. Security analyst loggings into the portal and provides necessary details.
2. The Traffic Light Protocol (TLP) governs the sharing of sensitive information.
3. A senior investigator activates prioritized monitoring across shifts, after review.
4. SOC automates hunts through customers data streams to match hot threat IOCs.
5. Successful attacks are analyzed, notifications are sent with guidance to mitigate harm.
6. Retired after 30 days or when their importance diminishes, but remain searchable.

## Open Web Application Security Project (OWASP)

### Overview of OWASP

- Founded in 2001.
- focuses on application security.
- Guides, cheat sheets, and tools for developers to secure applications.
- 3 year report of top 10 most exploited web application vulnerabilities, which serves as a critical resource for security professionals.
Top 6:
- **Injection**
- **Broken Authentication and Session Management**
- **Cross-Site Scripting (XSS)**
- **Insecure Direct Object References**
- **Security Misconfiguration**
- **Sensitive Data Exposure**

### Spamhaus Project

- Founded in 1998, 
- Nonprofit organization aimed at combating spam and malicious email.
- Protecting over 1.7 billion mailboxes globally.
- Analysts use to validate the legitimacy of emails.
- Help in tracking persistent spam operations.
Recources:
- **Top 10 Worst List** 
- **Spamhaus Block List (SBL)**
- **Exploits Block List (XBL)**

### Alexa

- A subsidiary of Amazon, 
- Specializes in website traffic analytics and ranks websites based on user engagement.
- Collects data through browser extensions and provides insights into the most popular websites on the internet.

- studies reveal that many top-ranked sites may still harbor security risks
- highlighting the need for caution even with popular domains.

#### Use in Security Analysis

- Tools like GoatRider utilize Alexa's rankings to assess the safety of web addresses, integrating this data into broader security assessments.
- Analysts should be aware of the potential risks associated with high-traffic sites, as they can still be exploited by malicious actors.

### Farsight Security’s DNSDB

- Catalogs passive and authoritative DNS data, providing insights into domain name system activities.
- Helps security analysts track DNS records, including their creation and modification dates.
- Analysts can verify the legitimacy of DNS requests related to suspicious activities.
- The bailiwick check ensures that additional DNS information is relevant to the original query, enhancing the accuracy of investigations.
- DNSDB can assist in identifying malicious domains and understanding their historical context.

# [[Security Tools Reference]]

Problem-Solving Steps

1. Identify the type of security threat or vulnerability.
2. Select the appropriate tool for assessment (e.g., Nmap for scanning, Wireshark for packet analysis).
3. Conduct the assessment using the selected tool.
4. Analyze the results to identify potential security issues.
5. Develop a remediation plan based on the findings.
6. Implement the remediation and monitor for any further issues.

Key Terms/Concepts

- **Cyber-attack**: An attempt to damage, disrupt, or gain unauthorized access to computer systems or networks.
- **Security Analyst**: A professional responsible for protecting an organization's data and information from cyber threats.
- **Vulnerability Assessment**: A systematic review of security weaknesses in an information system.
- **Incident Investigation**: The process of examining and analyzing security incidents to understand their cause and impact.

# [[Threat Investigation Example]]
— China Chopper Remote Access Trojan

#### Key Features

|Feature|Description|
|---|---|
|Command and Control|Allows attackers to conduct scans and brute force attacks on the infected server.|
|File Upload/Download|Attackers can upload additional malware or download sensitive data from the compromised server.|
|Language Support|Web shells can be written in various languages, including PHP, ASP, Perl, and Python.|
|Small Size|The web shell application is typically under 4KB, making it difficult to detect.|
#### Key Investigation Steps
- Alerts triggered by specific commands like '==id==' on UNIX systems.
- Queries identified in HTTP between the attacker’s client and the web shell.
- Neutralize the compromise, often involving re-imaging the affected system.
- Monitor and ensure that remediation steps have been completed.

#### Key Tools
- **Wireshark**: A network protocol analyzer used to capture and analyze HTTP traffic between the attacker’s client and the web shell.
- **Snort**: An intrusion detection system that can trigger alerts based on specific rules related to suspicious commands and traffic.
- **Bro**: A network analysis framework used to log and analyze network traffic, aiding in the investigation of security events.

#### Reference Information
- Snort rules can be used to detect China Chopper traffic.
- Wireshark can analyze HTTP traffic to reveal suspicious activities.
- Bro logs can be queried for event correlation during investigations.

#### Facts to Memorize
- The ==caidao.exe client== is the attacker's interface for China Chopper.
- Common web shell languages include ==PHP, ASP, Perl, Ruby, Python, and UNIX shell== scripts.
- The ==X-Forwarded-For HTTP header== is used to identify the ==originating IP== address of a client.
- The ==id command== is commonly used on UNIX systems to ==check privileges== of current process.

#### Features of China Chopper
- Command and Control (C2) capabilities allow attackers to scan for vulnerabilities and execute brute force attacks.
- Attackers can upload or download files, including additional malware, to and from the infected system.
- The web shell can be written in various programming languages, with PHP and ASP being the most common.
