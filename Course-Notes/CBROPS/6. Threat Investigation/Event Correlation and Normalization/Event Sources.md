# [[Quick Reference]]

Key Devices/Systems

|Device/System|Description|
|---|---|
|**DHCP Server**|Assigns dynamic IP addresses to devices on a network and logs transactions for tracking purposes.|
|**DNS Server**|Resolves domain names to IP addresses and logs queries and responses, useful for identifying suspicious activity.|
|**Firewall**|Monitors and controls incoming and outgoing network traffic based on predetermined security rules.|
|**Intrusion Prevention System (IPS)**|Monitors network traffic for suspicious activity and can take action to prevent breaches.|
|**Antivirus**|Detects and prevents malware infections on devices, often providing alerts and logs for incidents.|

Key Investigations

- **Traffic Analysis**: Using NetFlow data to establish a baseline of normal network behavior and identify anomalies.
- **Authentication Monitoring**: Analyzing AAA server logs for patterns of failed and successful authentication attempts to detect potential attacks.
- **Proxy Logs Review**: Examining web proxy logs for suspicious requests or blocked content to identify potential threats.

Key Techniques

- **Deep Packet Inspection**: A method used by firewalls to analyze the data part (payload) of network packets for security purposes.
- **Baseline Establishment**: The process of determining normal network behavior to identify deviations that may indicate malicious activity.
- **Content Filtering**: The practice of blocking or allowing content based on predefined policies, often implemented in proxy servers.

Key Alerts/Events

- **Failed Authentication Alerts**: Notifications generated by AAA servers indicating multiple failed login attempts, which may suggest a password attack.
- **Malware Detection Alerts**: Notifications from antivirus systems when a virus is detected, prompting immediate action to mitigate the threat.
- **Anomalous Traffic Alerts**: Alerts generated by NetFlow analysis when traffic exceeds established baselines, indicating potential data exfiltration or other malicious activities.

Facts to Memorize

- NetFlow v5 records include IP 5-tuple data: source IP, destination IP, source port, destination port, and transport protocol.
- NetFlow v9 and IPFIX are extensible and can include additional fields like username and MAC address.
- AAA stands for Authentication, Authorization, and Accounting.
- The common log format used by Apache web server logs client addresses and requested resources.

Reference Information

- DHCP server logs can help confirm device identity through MAC addresses.
- DNS logs can indicate potential malware campaigns through DGA domain names.
- IPS alerts can provide insights into potential security breaches and traffic anomalies.
- Proxy servers can block requests based on configured policies and provide transaction data.

Cause and Effect

|Cause|Effect|
|---|---|
|High volume of failed authentications|May indicate a password attack or unauthorized access attempts.|
|Unusual NetFlow traffic patterns|Could signify data exfiltration or a security breach if traffic exceeds normal baselines.|
|Triggering of IPS alerts|Indicates potential security threats that need to be investigated further.|
|Proxy server blocking requests|Protects the network from accessing malicious sites or content.|

Key Terms/Concepts

- **Event Data Source**: The origin of data that can be used to track events in a network, such as DHCP servers, DNS servers, and firewalls.
- **NetFlow**: A network protocol developed by Cisco for collecting IP flow information, widely used for monitoring network traffic.
- **Proxy Server**: A server that acts as an intermediary for requests from clients seeking resources from other servers, often used for content security.
- **Identity and Access Management (IAM)**: Solutions that manage user identities and access rights, providing audit trails and differentiated authorization based on various factors.

# Overview of Event Sources

### Types of Event Sources

- Events can originate from various devices, each providing different types of data relevant for security monitoring.
- Common event sources include DHCP servers, DNS servers, AAA servers, NetFlow-capable devices, IPS, firewalls, and proxies.
- The type of device determines the nature of the events that can be extracted, influencing the analysis and response strategies.

### Importance of Event Data

- Event data is crucial for identifying security incidents, understanding network behavior, and maintaining compliance.
- Analyzing event data helps in detecting anomalies, such as unauthorized access attempts or unusual traffic patterns.
- Correlating data from multiple sources enhances the accuracy of threat detection and response.

# Detailed Analysis of Event Data Sources

### DHCP Server

- ****Transaction Data****: Dynamic IP address assignments and attribution to hosts by MAC address.
- ****Example****: If multiple IOCs are detected from different IPs at various times, DHCP logs can confirm if they belong to the same device by checking the MAC address.
- ****Rationale****: This helps in tracking devices that roam across networks, providing insights into potential malicious activities.

### DNS Server

- ****Transaction Data****: Logs of DNS queries and responses are critical for identifying malicious domains.
- ****Example****: Detection of DGA (Domain Generation Algorithm) domain names often used in malware campaigns.
- ****Rationale****: Analyzing DNS logs can reveal suspicious activities, such as DNS tunneling, which may indicate data exfiltration attempts.

### AAA Server

- ****Alert Data****: Records of successful and failed authentication attempts.
- ****Example****: A series of failed logins followed by a successful one may indicate a password attack.
- ****Rationale****: Monitoring authentication events is essential for identifying unauthorized access and potential breaches.

# Network Traffic Analysis

### NetFlow Data

- ****Session Data****: NetFlow records include IP 5-tuples, byte counts, and timestamps, providing a comprehensive view of network traffic.
- ****Statistical Data****: NetFlow can generate reports on top conversations and hosts, helping to establish traffic baselines.
- ****Example****: An organization may notice unusual traffic patterns, such as excessive data transfers to specific countries, indicating potential data exfiltration.

### Intrusion Prevention System (IPS)

- ****Alert Data****: IPS generates alerts based on predefined rules and can capture packets related to triggered alerts.
- ****Example****: Alerts for spoofed DNS queries or potential malware downloads can be correlated with other network data for deeper analysis.
- ****Rationale****: IPS data is vital for real-time threat detection and response, enhancing overall network security.

# Firewalls and Proxies

# NetFlow Protocols

### Evolution of NetFlow

- NetFlow has undergone significant evolution, with multiple versions defined over the years, including NetFlow v5, v9, and IPFIX.
- NetFlow v5 is widely deployed but lacks support for IPv6, making it less relevant as networks transition to IPv6.
- NetFlow v9 and IPFIX are extensible protocols that allow for additional fields beyond the basic 5-tuple data, such as usernames and HTTP URLs.

### Key Features of NetFlow v5

- Records include the IP 5-tuple data: source IP, destination IP, source port, destination port, and transport protocol.
- Flow data also captures the number of bytes and packets transferred, providing insights into network traffic.
- Despite its limitations, NetFlow v5 remains a foundational tool for network traffic analysis.

### NetFlow Reporting and Analysis

- Top reports generated from NetFlow data, such as 'Top Conversations', provide statistical insights into host communication patterns.
- Example: A SYN flood attack from host 10.3.2.202 to server 10.3.1.120 on port 80 illustrates the utility of NetFlow in identifying security threats.
- Aggregated NetFlow data at the collector helps establish baseline values for normal network behavior.

### Baseline Values and Variance Analysis

- Baseline values help answer critical questions about network usage, such as expected application protocol traffic at specific times.
- Analysts can query baseline data to understand normal data transfer volumes and client-server interactions.
- Variance analysis over time can highlight anomalies that may indicate security incidents or performance issues.

# Proxy Servers

### Functionality of Proxy Servers

- Proxy servers provide content security by acting as intermediaries between clients and external servers.
- They require two connections: one from the client to the proxy and another from the proxy to the external server, allowing for request interception.
- Proxies can deny requests or responses based on configured policies, enhancing security and compliance.

### Email Proxy Operations

- Email proxies are often published as the Mail Transfer Agent (MX) record in DNS, directing incoming emails for inspection.
- They validate the reputation of SMTP sender IP addresses and can quarantine or drop connections from known spam sources.
- Email proxies may also perform virus scans on attachments, ensuring that malicious content is blocked before reaching users.

### Transaction and Session Data

- Proxy servers can log detailed transaction data, including the IP 5-tuple and the number of bytes and packets exchanged.
- Transaction data provides insights into specific client requests, such as URLs accessed and server responses.
- Example: Using the Open Source Squid web proxy to block access to gambling websites demonstrates practical application of proxy policies.

# Identity and Access Management (IAM)

### Overview of IAM Solutions

- IAM solutions like Cisco ISE provide comprehensive audit trails for network access, integrating with user repositories like AD or LDAP.
- They offer AAA (Authentication, Authorization, Accounting) services for various access methods, including wired, wireless, and VPN.
- Differentiated authorization allows for varying privileges based on user context, such as device type and connection method.

### Device Profiling and Posture Assessment

- IAM solutions can automatically determine the type of device connecting to the network, enhancing security posture.
- Posture assessment checks client systems for compliance with security standards before granting access.
- Non-compliant devices may be quarantined, limiting their access to only resources necessary for remediation.

### Audit Trails and Logging

- IAM logs provide detailed records of user identity, authentication, and authorization events, answering critical security questions.
- Example logs from Cisco ISE illustrate the application of policies and the tracking of user sessions.
- These logs are essential for forensic analysis and compliance reporting in security audits.

# Antivirus Solutions

### Core Functions of Antivirus Software

- Antivirus platforms primarily detect viruses on file systems, within emails, and during downloads, protecting against malware.
- Some antivirus products function as proxies, providing visibility into sessions and enabling full packet capture.
- Alerts are generated when viruses are detected, allowing for rapid incident response by security teams.

### Centralized Management and Logging

- Enterprise-grade antivirus solutions, such as McAfee ePolicy Orchestrator, allow for centralized log collection and configuration management.
- Centralized logging facilitates easier monitoring and analysis of security incidents across multiple devices.
- Alerts from client antivirus systems can be sent to a Security Operations Center (SOC) for immediate action.

# Application Logging

### Importance of Application Logs

- Application logs provide transactional and statistical data essential for monitoring application performance and security.
- The Apache web server, for example, uses a common log format to log client addresses and requested resources.
- Centralized logging of application data aids SOC analysts in correlating events and obtaining statistics.

### Use of Syslog for Remote Logging

- Syslog is a tool that enables remote logging capabilities, allowing logs to be sent to a centralized location for analysis.
- Centralized application logs are crucial for mission-critical applications, such as e-commerce payment processing systems.
- Collecting logs from various applications helps in identifying trends and potential security threats.
