## Security categories

- **Network security:** The practice of securing a computer network from all network threats. Network security can block attacks and allows only authorized access to network resources.
    
- **Application security:** The process of analyzing the security weaknesses of an application. The application security seeks to harden applications by adding security features, such as encryption.
    
- **Information security: T**he protection of privacy and data integrity. Information security helps ensure the availability of data during transmission or when stored. An example of a protective information security measure is using encryption and creating redundant copies of data.
    
- **Operational security:** The process of handling all the operation’s assets that a business requires for achieving its business goals. For instance, if an organization produces birthday cakes, operation security helps secure all the processes to produce a birthday cake. Operational security includes risk management so that there is a backup plan if resources become compromised. Operational security also helps employees have access to education in keeping personal and business information secure.
    
- **Disaster recovery:** Procedures that the organization follows to recover after a cyberattack or natural disaster.
    
- **End-user education:** Includes practices that involve educating users in social engineering techniques, how to recognize suspicious activities, how to follow security policies, and how to report incidents.


The following are important concepts to help you learn about cybersecurity and security posture:

- **Threat:** Any circumstance or event with the potential to cause harm to an asset. A threat can result in destruction, disclosure, adverse modification of data, or denial of service (DoS). An example of a threat is malicious software that targets workstations.
    
- **Vulnerability:** A weakness that compromises either the security or the functionality of a system. An example of a vulnerability is a weak or easily guessed password. An example of a vulnerable asset would be a computer system running an outdated operating system. The vulnerabilities can have several possible causes result from:
    
    1. Lack of quality control processes
        
    2. Unsupported legacy software applications
        
    3. Inherent product flaws or weaknesses
        
    4. Unpatched software defects
        
- **Exploit:** A mechanism that uses a vulnerability to compromise the security or functionality of a system. An example of an exploit is malicious code that is used to gain access to a system. When a vulnerability is disclosed to the public, attackers often create a tool that implements an exploit for the vulnerability. If they release this tool on the internet, other less-skilled attackers and hackers can then easily exploit the vulnerability.
    
- **Risk:** The likelihood that a particular threat that uses a specific attack will exploit a particular vulnerability of an asset that will result in an undesirable consequence.
    
- **Mitigation** **techniques:** Methods and actions that are used to protect against threats and exploits. An example of a mitigation technique is the practice of implementing updates and patches. Another example of a risk mitigation action is increasing the frequency of data backups. The purpose of these techniques is to reduce the possible impact and reduce risks.

# Security Posture

Cybersecurity posture refers to the status of actions taken to protect information resources from cyberattacks. The goal of cybersecurity is to create a strong and effective security posture.

- Security Posture Definition: The outcome of all protection, detection, and response capabilities implemented by an organization, consisting of people, processes, and technology.
- Factors Contributing to Security Posture: Policies established by management, technical elements like security controls and disaster recovery procedures, and the implementation of these measures by the security operations team.
- Security Posture Maintenance: Not a static state but an evolving and dynamic assessment that requires continuous evaluation and adjustment to remain effective as systems, technology, threats, and user habits change.

- Resilience Definition: The ability of a resource to adjust and continue operating under both expected and unexpected conditions.
- Resilience vs. Robustness: Resilience involves preparing for and recovering from failures, while robustness focuses on preventing failures.
- Benefits of Resilience: Improves security posture by enabling early detection and fast recovery from failures, reducing risk of system damage.

- Security Posture Assessment: Evaluates an organization’s security posture by analyzing its IT assets, security controls, and risk exposure.
- Asset Inventory: Maintains a comprehensive inventory of all IT assets, including their attributes, business impact value, and associated security costs.
- Security Controls: Covers all implemented security and privacy controls, including preventive, protective, and detection measures, and their effectiveness through continuous monitoring.

- Cybersecurity Risk Assessment: Evaluates the potential loss or harm to assets that cyber-attacks can cause.
- Security Investment Decision: Organizations must balance security and business agility, relying on CISOs for expert advice on security matters.

- CISO’s Role: Ensures security strategy aligns with business needs, advises on security during planning and design, and keeps business leaders informed about security status.
- Security Team’s Role: Implements security measures that align with business objectives and reports directly to the CISO.

- Compliance Strategy: Meeting the requirements of security regulations and frameworks like PCI-DSS and GDPR can help reduce cybersecurity risks and protect data.
- Compliance vs. Security Posture: Compliance alone doesn’t guarantee a strong security posture; data breaches can occur in compliant organizations.

- Security Investment Allocation: Businesses should quantify risk likelihood and impact to determine appropriate security investment, considering business requirements and potential threats.

- Achieving a Strong Security Posture: Requires a combination of technical solutions and a strong security culture throughout the organization.

- Security Strategy Goal: Keep resources safe from emerging threats and risks.

- Security Strategy Adaptation: Reflects the operational needs of the organization and continuously adapts to the organization’s goals.

- Security Tactics: Operational elements and methods chosen to achieve a strategic goal, including human resources plans, network segmentation, secure remote access, access controls, threat recognition training, software updates, and monitoring.

- AUP Compliance: Employees must sign the AUP, agreeing to comply with the outlined rules and policies, before accessing network resources.

- Policy Implementation: IT operational teams are responsible for implementing the compliance requirements outlined in the AUP, using various methods like configuring security policies on devices.

- AUP Role: The AUP serves as a document that outlines strategic requirements for data security and privacy, with tactics like onboarding procedures and device configuration used to meet those requirements.

# Security Assessments

 According to NIST, the goal of the security assessment is to determine the extent to which the security and privacy controls meet three qualifications:

- They are implemented correctly.
- They operate as intended.
- They produce the desired outcome regarding the security requirements for the system.

Each assessment is developed based on the assessment objectives. Objectives define what must be assessed and how. In more formal terms, objectives define the following:

- The subject under assessment, 
- The desired security status of the subject
- The method, depth, and coverage to verify the security status of the subjects

Before starting an assessment, make sure that the objectives are clearly defined.

Security assessments can evaluate multiple cybersecurity elements, from the technical implementation of the security controls, to measures intended to physically protect the asset. The following are some examples of security assessments:

- Vulnerability assessment
- Risk assessment
- Documentation, configuration, and code review
- Physical security test
- Penetration test

## Security Assessment Objectives, Objects, and Methods

To determine the assessment objects, ask yourself the two questions:

- Where can I get the information that I need?
- What controls, features, and documents can I assess?

The objects of the assessment can be as follows:

- **Specifications:** Document-based artifacts, such as written policies, procedures, plans, and architectural designs of the system.
- **Mechanisms:** Hardware, software, or firmware security capabilities that are used.
- **Activities:** Actions that involve people, such as system backup operations and traffic monitoring.
- **Individuals:** People applying the specifications, mechanisms, and performing activities.

NIST defines three assessment methods to evaluate assessment objects:

- Examinations: Review documentation, observe processes, check configurations, verify physical security, and study technical manuals and user guides. For instance, reviewing the IPS ruleset to ensure it aligns with security policies.
- Interviews: Facilitate discussions with individuals to gather evidence about assessment objectives.
- Tests: Create specific conditions to compare actual behavior with expected behavior. Security tests may include access controls, penetration of critical system components, backup operations, incident response, and physical access devices. The organization provides test considerations, including resources, features to test, and acceptable test actions, to help plan the test and address assessment objectives.

## Assessment Approaches

![8](/Course-Notes/.assets/Screenshot_2024-11-09_at_19.50.19.png)
### Internal assessments 
Inside perimeter assessments involve impersonating a user or insider threat adversary with internal access to the organization’s resources.

Internal assessments grant you privileged access to the target environment and relevant information. Internal testing offers fewer security controls to bypass, as perimeter controls can block assessment actions. Techniques like network sniffing (data packet capture) are better suited for internal testing, as capturing network traffic is easier with internal access.

### External assessments
Outside perimeter assessments involve impersonating an adversary outside the target’s security perimeter.

External tests better reflect real-world attack risks and test perimeter security controls designed to mitigate them. They usually start with gathering publicly available information, especially from open-source intelligence (OSINT) resources.

External and internal tests complement each other, as threats can originate from inside or outside the network. Penetration testers should test security controls against both external and internal threats. If both assessments are performed, the external test should be done first to avoid prematurely influencing testing decisions by internal results.

![7](/Course-Notes/.assets/Screenshot_2024-11-09_at_19.50.37.png)

(White) Crystal box (full knowledge): Involves the organization’s staff, who provide information about the environment being tested. This allows you to skip or reduce discovery activities. 
- This information may include network topology diagrams, asset lists, and configuration files. You can quickly recognize vulnerable operating system versions by reviewing this information manually. 

(Black) Dark box (zero-knowledge): Doesn’t involve the organization’s staff. You receive no information about the environment. It aims to determine how a real adversary could impact the organization and the damage it could cause. You mimic the adversary and try to stay undetected. Dark box tests require specific expertise and time.
- Specialized scanning tools, like network-mapping tools and vulnerability scanners, can provide information during a dark box test. Examples include Nessus, Nmap, Burpsuite, OpenVAS, ImmuniWeb, and Metasploit.

Gray box (partial knowledge): The organization’s staff provides limited knowledge of the systems or network before the test. This represents the knowledge of non-technical staff to simulate an insider threat. Additional discoveries are performed to obtain more information. You have the same privileges as a regular non-technical user.

## Vulnerability Assessments and Penetration Tests

![5](/Course-Notes/.assets/Screenshot_2024-11-09_at_19.54.13.png)

The target identification process, or target scanning, involves gathering preliminary information about the target, such as domain names, web URLs, network address ranges, and email addresses. This information can be obtained using OSINT techniques that rely on publicly available sources.

Once the preliminary information is gathered, additional information is enriched to identify specific assets, such as user computers, application-hosting servers, firewalls, and routers. Network scanning tools are used to identify the active assets.

After identifying the active devices, the services running on them are determined using scanning tools that recognize operating systems and applications. The collected information is manually analyzed or analyzed by an automated vulnerability scanner.  

A vulnerability scanner first identifies assets and services, creating a list of devices with their attributes. It then compares the discovered information with known vulnerabilities stored in its database, identifying any matches as vulnerabilities.

- Attack techniques that are successful against the system
- The level of expertise that an adversary requires to compromise the system (how easy it is to compromise the system)
- How fragile or resilient the system is in the case of a successful attack and what consequences such an attack could have
- Effectiveness of the defenses

- **Engagement rules:** Also known as the rules of engagement, these rules specify how assessments are conducted. ## Execution and Closure Stages
- **Discovery phase:** Gather information about the target and identify the vulnerabilities.
- **Attack phase:** Try to validate the discovered vulnerability. In the attack phase, you perform the following activities:
    
    1. Choose an exploit that fits the vulnerability and attempt to gain access to the target.
    2. Escalate the privileges.
    3. Browse the system to discover new information.
    4. Establish presence by introducing new adversarial tools to the target system.

## Security Assessment Legal Framework

Ensuring cybersecurity can be legally binding, especially for critical systems. The European Union’s Network and Information Security Directive and TIBER-EU framework provide a basis for this obligation. In the United States, frameworks like NIST Cybersecurity Framework, DoD CMMC 2.0, and NICCS framework exist.

Organizations customize their cybersecurity efforts to meet specific requirements, as there are no standardized cybersecurity regulations. Testing and risk assessments become obligatory security compliance mechanisms in some cases.

## Cybercrime Laws

Penetration testers must respect cybercrime laws in the countries they operate in. If their assessments span multiple countries, they must comply with the relevant legislation of all countries.

Law enforcement agencies may consider the assessor’s behavior a criminal offense, especially outside the security assessment context. Penetration tests can cause undesirable system effects, so assessors must be clear about their actions and shouldn’t be held accountable for consequences. Obtain authorization before starting assessments. Penetration testers must understand allowed system activities.

Before executing an assessment, ensure you have the “get-out-of-jail-free” permission document. It authorizes the assessment and entitles you to perform under specified conditions. Obtain the following documents:

- Permissions and contracts authorizing assessments against organization assets.
- Rules of engagement (RoE).
- Assessment scope.

Phishing attacks without explicit permission expose penetration testers to legal liabilities, even for testing purposes. As a penetration tester, obey contractual and regulatory limitations. If your SOC provides penetration testing, ensure it’s certified and qualified to conduct activities.

# Introduction to Cybersecurity

### Importance of Cybersecurity

- Cybersecurity is crucial in protecting sensitive data and maintaining privacy in an increasingly digital world.
- The reliance on information and communications technology (ICT) for daily tasks highlights the need for robust cybersecurity measures.
- Cybersecurity incidents, such as data breaches, can have severe consequences for individuals and organizations alike, affecting reputation and financial stability.
- Critical infrastructure sectors, including healthcare and utilities, depend on secure ICT resources to function effectively.
- Awareness of cybersecurity threats has grown due to media coverage of high-profile cyberattacks.

### Key Components of Cybersecurity

- Cybersecurity encompasses various elements, including system configuration, data encryption, and physical security.
- The goal is to protect devices, networks, services, applications, and data from unauthorized access and damage.
- Essential security services include confidentiality, integrity, and availability, collectively known as the CIA triad.
- Organizations must implement multiple layers of protection to safeguard their ICT resources effectively.
- The integration of people, processes, and technology is vital for a successful cybersecurity strategy.

### The CIA Triad

- ****Confidentiality****: Ensures that sensitive information is only accessible to authorized users.
- ****Integrity****: Guarantees that data remains accurate and unaltered unless modified by authorized individuals.
- ****Availability****: Ensures that authorized users have uninterrupted access to necessary resources and data.
- The CIA triad serves as a foundational concept in information security, guiding the development of security policies and practices.
- Organizations must balance these three principles to achieve comprehensive cybersecurity.

# Cybersecurity Approaches and Frameworks

### Traditional vs. Modern Cybersecurity Approaches

- Traditional cybersecurity focused on securing the perimeter of enterprise networks, assuming that threats primarily came from outside.
- Modern approaches recognize that threats can originate from both inside and outside the organization, necessitating a more holistic view.
- The shift towards remote work and cloud-based applications has transformed how cybersecurity is implemented.
- Zero-trust security has emerged as a leading approach, emphasizing continuous verification of users and devices before granting access.
- Organizations must adapt their cybersecurity strategies to align with evolving work habits and technological advancements.

### Zero-Trust Security Model

- The zero-trust model operates on the principle of 'never trust, always verify'.
- It requires verification of every user and device attempting to access organizational assets, regardless of their location.
- Trust is established through rigorous identity verification and assessment of the security posture of devices.
- This model helps mitigate risks associated with insider threats and compromised credentials.
- Implementing zero-trust requires a combination of technologies, policies, and user education.

### Cybersecurity Frameworks

- Frameworks like the NIST Cybersecurity Framework provide structured guidelines for organizations to enhance their cybersecurity posture.
- These frameworks help organizations identify, protect, detect, respond to, and recover from cyber threats.
- Utilizing established frameworks can streamline the development of security policies and procedures.
- Organizations can customize frameworks to fit their specific needs and risk profiles.
- Continuous evaluation and adaptation of frameworks are essential to address emerging threats.

# Zero Trust Security Model

### Overview of Zero Trust

- The zero-trust security model operates on the principle of 'never trust, always verify'. This means that every user and device must be authenticated and authorized before accessing any resources, regardless of their location.
- It emphasizes continuous verification of user and device identities, ensuring that access is granted based on multiple attributes such as device type, operating system, and user location.
- Contextual data, including recent user activity, is also considered during the verification process to enhance security.
- Multifactor authentication (MFA) is a critical component of zero trust, requiring users to provide additional verification beyond just a password.
- Example technology: Cisco Secure Access by Duo MFA automates the verification process, ensuring that only trusted entities gain access to resources.
- Continuous monitoring of user and device behavior is essential; any signs of malicious activity can lead to revocation of access.

### Implementation of Zero Trust

- An example of zero-trust implementation is the Cisco Continuous Trusted Access solution, which integrates various security measures to maintain a secure environment.
- The zero-trust model requires organizations to adapt their security policies and practices to align with this approach, focusing on granular access controls.
- Organizations must regularly assess and update their security posture to respond to evolving threats and vulnerabilities.
- The role of a Security Operations Center (SOC) is crucial in monitoring and analyzing security events, providing real-time responses to potential threats.
- SOC analysts must stay informed about trends in the IT landscape to effectively implement new cybersecurity measures.
- Collaboration with other stakeholders is vital for a comprehensive security strategy, as SOCs often recommend policy changes based on threat analysis.

# Key Cybersecurity Concepts

### Threats and Vulnerabilities

- A threat is defined as any circumstance or event that has the potential to cause harm to an asset, such as malicious software targeting workstations.
- Vulnerabilities are weaknesses that compromise the security or functionality of a system, like weak passwords or outdated software.
- Common causes of vulnerabilities include lack of quality control, unsupported legacy software, and unpatched software defects.
- Understanding the relationship between threats and vulnerabilities is essential for effective risk management.
- Example: A vulnerability in an outdated operating system can be exploited by malware, leading to data breaches or system failures.
- Organizations must conduct regular vulnerability assessments to identify and mitigate potential risks.

### Risk Management and Mitigation Techniques

- Risk is the likelihood that a specific threat will exploit a vulnerability, resulting in undesirable consequences for an asset.
- Mitigation techniques are actions taken to protect against threats, such as implementing updates and increasing data backup frequency.
- Effective risk management involves identifying potential risks, assessing their impact, and implementing strategies to minimize them.
- Example of a mitigation technique: Regularly updating software to patch known vulnerabilities reduces the risk of exploitation.
- Organizations should develop a risk management framework that includes continuous monitoring and improvement of security measures.
- Training employees on security best practices is a critical component of risk mitigation.

# Attack Surface and Attack Vectors

### Understanding Attack Surface

- The attack surface is the sum of all security risks present in an environment that can be exploited by attackers.
- Reducing the attack surface is crucial for improving an organization's security posture, as it limits the number of potential entry points for threats.
- The attack surface can be categorized into four main areas: People, Network, Software, and Physical.
- Example: Implementing secure network protocols can reduce the network attack surface by ensuring data integrity and confidentiality.
- Organizations should regularly assess their attack surface and implement strategies to minimize it, such as removing unnecessary services or applications.
- A smaller attack surface makes it more challenging for attackers to find vulnerabilities to exploit.

### Common Attack Vectors

- Attack vectors are methods or paths that adversaries use to exploit vulnerabilities in a system.
- Common attack vectors include phishing emails, weak user credentials, and unpatched software.
- Social engineering attacks, such as impersonating IT support or using malicious USB drives, exploit human psychology to gain unauthorized access.
- Organizations must educate employees about these attack vectors to enhance their security awareness and reduce the risk of successful attacks.
- Example: Phishing emails can trick users into revealing sensitive information, leading to data breaches.
- Regular security training and awareness programs can help mitigate the risks associated with these attack vectors.

# Network Access Control and Attack Surfaces

### Understanding Network Access Control

- Network access control (NAC) is a security approach that determines whether a device can connect to a network based on predefined security policies.
- NAC addresses two fundamental questions: 'Am I allowed to access this device from another device?' and 'Should I be allowed to?'.
- Effective NAC can prevent unauthorized access and mitigate risks associated with network-based attacks.
- Common network-based attacks include unauthorized network access, spoofing, and exploitation of poorly configured protocols.
- Implementing NAC involves authentication mechanisms, such as passwords, biometrics, or certificates, to verify user identity.

### Common Network-Based Attacks

- ****Unauthorized Network Access****: Attackers gain access to the network without proper authentication, often exploiting weak passwords or unsecured networks.
- ****Spoofing Attacks****: Attackers impersonate legitimate devices or users to intercept or manipulate data, often through man-in-the-middle techniques.
- ****Exploiting Open Ports****: Attackers take advantage of open and poorly configured ports to gain unauthorized access to systems and data.
- ****Case Study****: The 2014 Target data breach involved attackers exploiting network vulnerabilities to access customer payment information.

### Software Attack Surface

- The software attack surface encompasses vulnerabilities in applications, operating systems, and APIs used within an organization.
- Common software vulnerabilities include lack of encryption, outdated systems, and poorly implemented APIs.
- Organizations must regularly update and patch software to mitigate risks associated with known vulnerabilities.
- Example: The Equifax breach in 2017 was largely due to unpatched software vulnerabilities, leading to the exposure of sensitive data for millions.

### Physical Attack Surface

- The physical attack surface refers to vulnerabilities in physical security that can lead to unauthorized access to systems and data.
- Examples include unattended workstations, unsecured network equipment, and improper disposal of decommissioned hardware.
- Organizations should implement strict physical security measures, such as access controls and surveillance, to protect against physical threats.

# Reducing the Attack Surface

### Importance of Reducing the Attack Surface

- Reducing the attack surface is crucial for minimizing risks and enhancing cybersecurity measures within an organization.

# Overview of Security Testing

### Purpose of Security Testing

- Security testing aims to evaluate the security capabilities of an organization, focusing on protection, detection, and response capabilities.
- It provides recommendations for improvements based on the assessment results.
- Security tests can demonstrate compliance with legal requirements or security frameworks, ensuring that organizations meet necessary standards.
- Tests are more intrusive than examinations, potentially revealing sensitive information or rendering systems unavailable during the process.
- Combining multiple assessment methods yields more accurate results than relying on a single method.

### Types of Security Tests

- ****Network Discovery Tests****: Identify existing systems, services, and the software that implements them.
- ****Vulnerability Scans****: Identify software vulnerabilities within the organization's systems.
- ****Penetration Tests****: Attempt to exploit identified vulnerabilities to assess the security posture.
- ****Compliance Tests****: Check whether the operational state aligns with legal or framework requirements.
- Each type of test has specific objectives and prerequisites that must be met before execution.

# Assessment Approaches

### Internal vs. External Assessments

- ****Internal Assessments****: Conducted by impersonating a user or insider threat with access to the organization's resources.
- Internal testing benefits from fewer security controls to bypass, allowing for more effective testing techniques like network sniffing.
- ****External Assessments****: Simulate an adversary from outside the organization's security perimeter, reflecting real-world attack risks.
- External tests begin with gathering publicly available information, utilizing open-source intelligence (OSINT) resources.
- Both internal and external tests are complementary, addressing threats from both inside and outside the network perimeter.

### Test Models

- ****Crystal Box (Full Knowledge)****: Involves the organization's staff providing information about the environment, allowing for reduced discovery activities.
- ****Dark Box (Zero-Knowledge)****: No information is provided to the tester, simulating a real adversary's approach and requiring specific expertise.
- ****Gray Box (Partial Knowledge)****: Limited knowledge is shared, simulating a non-technical insider threat while allowing for additional discovery activities.
- The choice of test model impacts the assessment's depth and the tester's approach.

# Security Testing Phases and Prerequisites

### Phases of Security Testing

- ****Preparation****: Involves gathering considerations from the organization regarding resources and acceptable test actions.
- ****Execution****: The actual testing phase where the tester engages with the assessed object to provoke its security characteristics.
- ****Reporting****: Documenting findings, recommendations, and compliance status based on the test results.
- ****Follow-Up****: Addressing any identified vulnerabilities or compliance issues post-assessment.

### Test Prerequisites and Constraints

- Prerequisites specify requirements that must be met before testing begins, such as permissions and access levels.
- Constraints outline what actions are permissible during the test, ensuring compliance with legal and organizational policies.
- Understanding the legal background is crucial, as certain activities may require explicit permissions to conduct.
- The assessment policy of the organization determines the frequency and scope of each assessment, often based on regulatory compliance needs.

# Vulnerability Assessments vs. Penetration Tests

### Distinguishing Between Assessments

- ****Vulnerability Assessments****: Focus on identifying vulnerabilities without exploiting them, providing a broad overview of security weaknesses.
- ****Penetration Tests****: Involve actively exploiting vulnerabilities to assess the security posture and the potential impact of an attack.
- According to NIST, the execution of security tests can be grouped into two targets: identification and vulnerability validation.
- Understanding the differences in activities performed during each type of assessment is essential for effective security management.

### Execution of Security Tests

- The execution phase includes a sequence of activities that lead to the identification of vulnerabilities in the assessed objects.
- Proper documentation and interpretation of results are critical, as automated tools may not provide entirely accurate outputs.
- Tools like Network Mapper (Nmap) can assist in conducting network discovery tests, but results must be analyzed carefully.

# Overview of Vulnerability Assessments and Penetration Tests

### Definitions and Distinctions

- Vulnerability assessments and penetration tests are both security assessments but serve different purposes.
- Vulnerability assessments focus on identifying and validating known vulnerabilities without exploiting them.
- Penetration tests aim to exploit vulnerabilities to demonstrate potential impacts and risks.
- Understanding the differences is crucial for effective security management and risk assessment.

### NIST Guidelines

- According to NIST, security tests consist of activities grouped into two targets: identification and vulnerability validation.
- The identification phase involves discovering vulnerabilities in the assessment targets, while validation confirms their exploitability.

### Information Gathering Techniques

- The target identification process begins with gathering preliminary information such as domain names and network addresses.
- OSINT (Open Source Intelligence) techniques are used for passive reconnaissance to collect publicly available data.
- After preliminary data collection, active scanning identifies specific assets and their attributes.

# Overview of Penetration Testing

### Definition and Purpose

- Penetration testing, also known as ethical hacking, simulates real-world cyber attacks to identify vulnerabilities in systems.
- The primary goal is to assess the security posture of an organization and provide insights into potential risks.
- Unlike malicious hackers, ethical hackers operate under strict guidelines and time constraints, ensuring minimal disruption to operations.

### Importance of Penetration Testing

- Helps organizations understand successful attack techniques and the level of expertise required to exploit vulnerabilities.
- Assesses the resilience of systems against attacks and the potential consequences of successful breaches.
- Provides actionable insights on improving security measures and closing gaps in security controls.

### Key Differences: Vulnerability Assessment vs. Penetration Testing

- A vulnerability assessment identifies potential vulnerabilities, while penetration testing actively exploits them to demonstrate risk.
- Example: A vulnerability scan may reveal an unpatched server, but a penetration test confirms whether the vulnerability can be exploited and to what extent.
- Penetration tests can reveal the effectiveness of access controls and the potential for privilege escalation.

# Stages of Penetration Testing

### Preparation Stage

- Define the scope of the test, including which systems and techniques will be assessed.
- Establish rules of engagement to ensure that testing does not disrupt operations or expose sensitive data.
- Gather necessary documents, including engagement rules and the scope of assessment, to guide the testing process.

### Execution Stage

- The execution phase consists of two main parts: discovery and attack.
- Discovery involves gathering information about the target and identifying vulnerabilities.
- The attack phase validates discovered vulnerabilities by attempting to exploit them, escalating privileges, and establishing a presence on the system.

### Closure Stage

- At the conclusion of the test, a detailed report is created summarizing findings and recommendations.
- The report includes a security risk assessment of vulnerabilities discovered during the test.
- It is crucial to communicate findings effectively to stakeholders to facilitate remediation efforts.

### Importance of Rules of Engagement
